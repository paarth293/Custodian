# Contributing

## Development setup

See [Getting started](README.md#getting-started) for prerequisites and build
commands. Recommended editor extensions are listed in `.vscode/extensions.json`.

## Before opening a pull request

Run the checks for every area you touched; CI runs all of them:

```sh
cargo fmt --all && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace
npm run format && npm run lint && npm run typecheck && npm test
ruff format . && ruff check . && mypy . && pytest
```

## Definition of done

1. Formatters and linters pass with zero warnings.
2. New or changed behaviour has tests. **No test touches real user folders**:
   use a temporary directory or a `FixtureRoot` (generated by `custodian-fixtures`).
3. No dead code, commented-out code or TODOs.
4. Security controls described in the architecture are implemented, or the gap
   is recorded in [`HONESTY.md`](HONESTY.md).
5. Changes to shared types start in `proto/` and are regenerated with
   `npm run proto:gen`.

## Build-plan workflow

Implement steps in order from the [build plan](docs/design/CUSTODIAN_BUILD_PLAN.md).
A commit that completes a step uses the message `Step NNN: <title>`.

Other changes (fixes, refactors, docs) use
[Conventional Commits](https://www.conventionalcommits.org/): `fix:`, `refactor:`,
`test:`, `docs:`, `chore:`.
