# Completion means verified behavior

The target is the user journey in the offline-assistant roadmap: delegate a task
in ordinary language, continue working, see measured and verified results, and
have a dependable way back. A successful build or simulated workflow does not
establish product completion.

Backend tests, model evaluations, packaging checks and interactive desktop
checks are different evidence and cannot substitute for one another.

The [Stage 3 language/planning report](../verification/STAGE-3-LANGUAGE-AND-PLANNING-2026-10-18.md)
records the frozen 36-case file-language evaluation separately from actual
native file execution, sandboxed runtime checks and desktop acceptance. It
accepts only the declared registered file combinations. General references,
content exclusions, multilingual execution, real app control and a new clean
installation remain open; Laya is inactive.

The [Stage 2 coordinator report](../verification/STAGE-2-TASK-COORDINATOR-2026-10-18.md) separates
real receipt-backed file composition from mocked app steps. Its stage gate is
the bounded coordinator foundation; it does not accept general language
planning, real multi-app execution or installation of a new product build.

The [17 October routine backup increment](../verification/ROUTINE-BACKUP-IMPLEMENTATION-2026-10-17.md)
adds separately recorded standing-permission and automatic-copy evidence. It
does not close the broader operator, model reliability or installation gates
below; the 16 October table remains a historical foundation snapshot.
The [model-planned collections report](../verification/MODEL-PLANNED-WORKFLOWS-2026-10-17.md)
separately records constrained model planning, group recovery and actual desktop

The [Stage 1 authority/recovery report](../verification/STAGE-1-AUTHORITY-AND-RECOVERY-2026-10-18.md)

It does not close general app control, compiler hardening, signing, installation

## Evidence rules

- Record commands, outcomes, model and environment. Preserve failing cases and
  their original expected answers.
- Mark checks not run when they were not run. Generating an installer does not
  prove installation; a transport ping does not prove inference readiness.
- Model metrics describe their harness. Deletion-claim checks are not a general
  security evaluation.
- Verify the shipped CPU model and optional GPU model separately. Passing with
  the development GPU model does not accept the bundled CPU experience.
- Retain interrupted-operation evidence. Never replay changes automatically
  after restart or claim completion without verification.
