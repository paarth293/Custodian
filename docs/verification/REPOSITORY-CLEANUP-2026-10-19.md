# Repository cleanup verification — 19 October 2026

This change separates maintained source from generated and machine-local
outputs. It does not replace the existing product implementation or mark
unfinished capabilities as accepted.

## Changes

- Retained the app/crate/service/schema boundaries used by Cargo, npm and Tauri.
  All 344 files fingerprinted in those existing trees remain byte-identical.
- Removed 30 generated fixture files and the already-deleted local project ID
  from Git's index. Existing local fixture data and markers remain available.
- Moved the two unreferenced root Cubby PDFs into ignored
  `.local/design-references/`, verifying their hashes after the move. They total
  18,240,546 bytes. The application's versioned SVG/PNG assets remain unchanged.
- Relocated `test_inference.mjs` to
  `services/agent/eval/inference-benchmark.mjs`, preserving the model location
  relative to the repository and documenting the developer-only benchmark.
- Deleted reproducible Python/tool caches. They may be regenerated by later
  developer checks and remain ignored.
- Removed the nonfunctional mock `tools/fetch.ps1`; there were no active source,
  package or CI consumers. The external-tool implementation gap is documented
  accurately in `HONESTY.md`. The unused `tools/` placeholder was also removed.
- Replaced the obsolete proposed-video script/captions with the actual rendered
  film's storyboard, script and captions under `video/custodian-explainer/`.
  The rendered MP4 and its local download path are preserved unchanged.
- Added a documentation index, evidence-retention guidance, source ownership
  rules and shared editor formatting defaults.
- Excluded local archives, output directories, recordings and caches from Git,
  format/lint/type scans and Docker build context where applicable. Secret
  scanning skips the new local output roots without hiding maintained nested
  source directories with similar names.
- Added `npm run repo:check` and a CI hygiene job. The check rejects ignored
  files already in Git, misplaced root files, oversized source assets, and
  missing workspace or Docker dependency-stage manifests.
- Added the editor-adapter manifest missing from Docker's dependency stage.
  Expanded pytest discovery to include `tests/`, including the existing Cedar
  fixture tests previously outside the configured test paths.

## Boundaries

The original worktree already contained implementation changes, missing files
and untracked source. They were preserved. Only cleanup-owned removals were
staged; no commit, push, reset or Git history rewrite was performed. The PDFs
and fixture files were removed from the next versioned tree, not from existing
Git history. This is not a claim that the repository's historical object store
became smaller.

Python checks ran with the available Python 3.11 interpreter; the project still
pins Python 3.12. Docker is unavailable here, so the container configuration was
checked structurally, not built or executed. Full installed-product, model
quality and disposable Windows acceptance remain separate gates. Clippy also
reported host filesystem hard-link fallback messages; strict code lint passed.

## Documentation cleanup follow-up

The first pass left too many loose reports and unreferenced run files. The
follow-up moved 45 documents into purpose-based categories and reduced the
documentation root from 46 files to one index. Architecture decisions now live
under `docs/design/decisions/`. There are five top-level documentation categories:
design, plans, reference, verification and retained evidence.

Archived 303 unreferenced raw logs and two duplicate HTML exports locally under
`.local/repository-archive-2026-10-19/`, preserving original paths and SHA-256
hashes in its manifest. Of those 305 files, 142 were tracked and were removed
from Git's index; the remainder were untracked or ignored outputs. Documentation
files on disk decreased from 659 to 354. Original logs remain available locally;
the archive is excluded from Git and does not accompany a fresh clone.

The migration was validated in a temporary candidate tree before changing the
active documentation. All 379 previously existing local links were checked,
including three links to preserved local-only assets. The capability register's
evidence aliases, verifier paths and generated Markdown were updated. All 95
frozen and historical JSON files remained byte-identical, and acceptance
validation passed for 58 requirements, 17 routes and 15 frozen cases. No
acceptance expectations or product-stage completion claims changed.

After migration, all 344 production source fingerprints remained unchanged.
Repository hygiene, JavaScript syntax checks, Prettier, ESLint, the secret scan
and Git whitespace checks passed. The new layout guard correctly rejected
temporary probes representing a loose root document and an HTML export, then
passed after their removal. This follow-up did not rerun runtime tests; the
full-suite results above belong to the first pass. No commit or push was made.
